# 日报模板

## 格式规范

```
序号、【分类】【项目】—子系统：工作内容描述。（工单编号：XXXXX）
```

## 分类选项

| 分类 | 使用场景 |
|-----|---------|
| 功能开发 | 新功能从0到1的开发 |
| 问题排查 | 定位问题原因但未修复 |
| 问题修复 | 已定位并修复问题 |
| 数据处理 | 数据迁移、清洗、SQL操作 |
| 对接 | 前后端对接、第三方接口对接 |
| 功能优化 | 对已有功能的改进优化 |
| 会议讨论 | 需求评审、技术讨论等会议 |
| 其他 | 不属于以上分类的工作 |

## 示例

```
1、【功能开发】【上海】-人员管理：进行人员请假功能的开发，完成基础的api对接。（工单编号：202601130915000200085）

2、【问题排查】【大连B】-碾压施工管控：图形报告显示桩点位置错误的问题。原因：施工单位传输坐标错误（工单编号：202601130915000200087）

3、【问题修复】【大连A】-数字沙盘：强夯施工未正确显示实时位置，已进行修复。原因：代码逻辑判断错误（工单编号：202601130915000200088）

4、【功能开发】【开发部】-流程引擎：开发抄送功能，已完成100%（工单编号：无）
```

## 填写要点

1. **项目名称**要准确（上海/大连A/大连B/开发部 等）
2. **子系统**要具体到模块（如：人员管理、碾压施工管控、数字沙盘）
3. **修复类**必须附上原因说明
4. 无工单编号时写"无"
5. 一条日报对应一个独立的工作事项
